## Descripción

Sea cual sea el sistema de base de datos, la apertura de una conexión es un proceso costoso en recursos tanto para el cliente como para el servidor:

* Asignación de memoria y acceso a disco para los buffers.
* Intercambios de red para el protocolo de conexión.
* Coste de CPU asociado.

La práctica habitual consiste en implementar un pool de conexiones. Este permite optimizar tanto la gestión de las conexiones como el rendimiento. Sin embargo, su configuración no siempre es trivial (requiere supervisar su comportamiento para encontrar el ajuste correcto). No obstante, siempre que la aplicación pueda evitar un acceso a la base de datos, ¡se debe evitar!

## Ejemplo

HikariCP es un pool de conexiones JDBC sólido y eficiente, integrado en SpringBoot.

En los casos donde no se disponga de un pool de conexiones, se debe reutilizar la conexión existente y no abrir/cerrar una nueva en cada petición.
