## Descripción

Sea cual sea el sistema de base de datos, la apertura de una conexión es un proceso costoso en recursos para el cliente y el servidor:

* asignación de memoria y acceso a disco para los buffers;
* idas y vueltas de red para el protocolo de conexión;
* coste de CPU inducido.

La buena práctica que se utiliza usualmente es la implementación de un pool de conexiones. Este último permite optimizar la gestión de las conexiones así como el rendimiento. Sin embargo, su configuración no es necesariamente una operación trivial (esto requiere supervisar el comportamiento del mismo para encontrar la configuración correcta). Dicho esto, ¡cada vez que la aplicación pueda evitar un acceso a la base de datos, hágalo!

## Ejemplo

HikariCP es un pool de conexiones JDBC sólido y eficiente. Está integrado en SpringBoot.

En los casos donde no hay un pool de conexiones, reutilizar una conexión y no abrir/cerrar una nueva conexión en cada petición.
