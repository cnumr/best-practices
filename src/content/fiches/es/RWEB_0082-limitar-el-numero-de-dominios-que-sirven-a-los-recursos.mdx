## Descripción

Cuando un sitio web o servicio en línea aloja los componentes de una página web en varios dominios, el navegador debe establecer una conexión HTTP con cada uno de estos dominios. Una vez recuperada la página HTML, el navegador llama a los recursos a medida que recorre el DOM (Document Object Model). Esto puede alargar el tiempo de espera antes de que la página esté operativa. En la medida de lo posible, es necesario agrupar todos los recursos en un mismo dominio.

La única excepción a esta regla es el alojamiento de recursos estáticos (hojas de estilo, imágenes, etc.) en un dominio separado (véase la buena práctica n.º 81), para evitar transportar cookies inútiles. Se reduce así el tiempo de respuesta y el ancho de banda consumido inútilmente.

## Ejemplo

Para un sitio web institucional de alto tráfico, se dará prioridad a dos dominios:

* el servidor de aplicaciones en www\.dominio.tld;
* el servidor multimedia «cookie-less» en media.dominio.tld.

Esto limita el número de dominios, evitando al mismo tiempo el transporte innecesario de una cookie en cada GET HTTP sobre un recurso estático.
