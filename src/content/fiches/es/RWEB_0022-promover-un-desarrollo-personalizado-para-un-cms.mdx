## Descripción

Utilizar un framework o un desarrollo a medida permite beneficiarse de una mayor libertad en la optimización de ciertos procesos.

Los CMS son más restrictivos e imponen funcionamientos que, a veces, consumen muchos recursos para alcanzar su principal objetivo: la flexibilidad. Por otra parte, el uso de un número excesivo de extensiones puede consumir muchos recursos y ralentizar el sitio.

Sin embargo, se puede utilizar un CMS muy ligero y modular, tal como un generador de sitio estático (Jekyll, Hugo, Gatsby, Eleventy, etc.) administrado por un headless CMS o CMS de "archivo plano" (Strapi, Contentful, Flextype, etc.) con el fin de reducir el tiempo de desarrollo.

## Ejemplo

En el caso de un sitio web corporativo (sitio de presentación) cuya información se actualiza raramente, se recomienda priorizar un sitio web estático previendo algunas jornadas de trabajo para la actualización. Si una funcionalidad necesita interacciones con el usuario, es preferible optar por un desarrollo a medida.
