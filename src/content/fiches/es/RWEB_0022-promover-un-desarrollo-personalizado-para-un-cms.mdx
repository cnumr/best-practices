## Descripción

Utilizar un framework o un desarrollo a medida, con el fin de beneficiarse de una mayor libertad en la optimización de ciertos procesos.

Los CMS son, en efecto, más restrictivos e imponen funcionamientos a veces exigentes en recursos para alcanzar su principal objetivo: la flexibilidad. Por otra parte, el uso de un número demasiado importante de extensiones puede consumir muchos recursos y ralentizar el sitio.

Sin embargo, se puede utilizar un CMS muy ligero y modular tal como un generador de sitio estático (Jekyll, Hugo, Gatsby, Eleventy, etc.) administrado por un CMS desacoplado o de archivo plano (Strapi, Contentful, Flex-type, etc.) con el fin de ganar tiempo de desarrollo.

## Ejemplo

En el caso de un sitio escaparate (sitio de presentación) cuya información se actualiza raramente, priorice un sitio web estático previendo algunos días-hombre para la actualización. Si una funcionalidad necesita interacciones con el usuario, priorice un desarrollo a medida.
