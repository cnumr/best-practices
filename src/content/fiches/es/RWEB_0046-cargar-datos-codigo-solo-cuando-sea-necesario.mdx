## Descripción

Para mejorar el rendimiento percibido, puede resultar tentador precargar recursos que podrían ser utilizados si el usuario realiza una acción específica (incluida la navegación hacia otra página).

Sin embargo, si dicha acción no se lleva a cabo, estas precargas solo habrán servido para desperdiciar recursos.

## Ejemplo

Evitar \<link rel="prerender">, así como todos los rel="preload", rel="prefetch", rel="preconnect", rel="modulepreload" y rel="dns-prefetch" cuyo recurso no se vaya a utilizar en la página actual, o que se utilice únicamente bajo ciertas condiciones.

Evitar la carga y el almacenamiento en caché (o en local storage) de datos de aplicación, como listas de valores y otros datos de referencia, si no existe la certeza absoluta de que serán utilizados.

Por extensión, se recomienda dividir el código JS, e incluso el CSS, en fragmentos (chunks) relativos a acciones particulares del usuario, y cargar dichos fragmentos solo cuando sean necesarios. Esto es especialmente válido para las SPA (Single Page Applications), donde cada pantalla (o posiblemente un conjunto de pantallas) podrá cargarse bajo demanda.
