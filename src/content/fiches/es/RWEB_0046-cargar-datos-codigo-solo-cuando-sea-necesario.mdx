## Descripción

Por razones de rendimiento percibido, puede resultar tentador precargar recursos que podrían ser utilizados si el usuario realiza una acción específica (incluida la navegación hacia otra página).

Pero si esta acción no se lleva a cabo, estas precargas no habrán servido más que para desperdiciar recursos.

## Ejemplo

Evitar \<link rel="prerender">, así como todos los rel="preload", rel="prefetch", rel="preconnect", rel="modulepreload" y rel="dns-prefetch" cuyo recurso no será utilizado en la página actual, o utilizado únicamente bajo ciertas condiciones.

Evitar las cargas y el almacenamiento en caché (o en almacenamiento local) de datos de aplicación, como listas de valores y otros referenciales, si no es absolutamente seguro que serán utilizados.

Por extensión, dividir el código JS, e incluso las CSS, por porciones (chunks) relativas a acciones particulares del usuario, y no cargar estas porciones más que cuando sean necesarias. Esto es especialmente cierto para las SPA (Single Page Applications), donde cada pantalla (o eventualmente conjunto de pantallas) podrá ser así cargado únicamente bajo demanda.
