## Descripción

Si una página se actualiza con muy poca frecuencia, es preferible optar por páginas estáticas, construidas fuera del CMS. Esto permite ahorrar ciclos de CPU y ancho de banda.

El uso de un sistema de gestión de contenido (CMS) dinámico requiere cargar las diferentes capas de software para servir el contenido solicitado por el usuario: el servidor HTTP, el servidor de aplicaciones, el sistema de almacenamiento (base de datos), y eventualmente los sistemas de caché asociados. En cambio, un archivo estático es leído directamente y reenviado al usuario por el servidor HTTP o el servidor de caché, sin solicitar al servidor de aplicaciones ni a la base de datos.

## Ejemplo

En función del servicio digital que se vaya a desarrollar, es posible considerar:

* Para una landing page o un sitio web informativo simple: crear un sitio estático en HTML, CSS y JS.
* Para un blog con poca actividad o tamaño pequeño: crear un sitio estático generado vía Jamstack (Jekyll, Hugo, Gatsby, Eleventy, etc.) administrado, si es necesario, a través de un headless CMS o un headless flat-file CMS (Strapi, Contentful, Flextype, Cecil.app, etc.).
* Para un sitio o aplicación web más compleja: convertir en estáticas las páginas con baja tasa de modificaciones (FAQ, Quiénes somos, Aviso legal, etc.) utilizando frameworks adaptados (Next.js, Nuxt.js, Svelte, etc.).
