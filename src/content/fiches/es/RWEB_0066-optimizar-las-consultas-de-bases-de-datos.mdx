## Descripción

Las consultas realizadas para recuperar y registrar datos tienen un impacto significativo en el consumo de recursos y, por tanto, deben optimizarse. Existen numerosas estrategias clásicas de optimización:

* Traer menos datos y limitarse a lo necesario.
* Seleccionar únicamente los campos necesarios.
* Añadir índices a los campos utilizados como claves. Esto puede reducir drásticamente la potencia de cálculo necesaria para la consulta.
* Analizar las consultas para identificar puntos de mejora, por ejemplo, mediante EXPLAIN en un SGBD Relacional.
* Almacenar en caché el resultado de las consultas más costosas y frecuentes.
* Si es necesario, desnormalizar el modelo de datos para evitar las uniones (joins), que pueden ralentizar las consultas.

## Ejemplo

Si solo desea mostrar los 25 primeros registros de una tabla, reemplace la selección completa:

```sql
SELECT firstname, lastname FROM people
```

Por:

```sql
SELECT firstname, lastname FROM people LIMIT 0, 25
```

Otro ejemplo, con la creación de un índice:

```sql
CREATE INDEX idx_FName_LName ON people(firstname, lastname)
```

Tras este comando, el sistema de gestión de base de datos podrá encontrar más rápidamente las líneas de la tabla people a partir de la información de nombre y apellido.
